Implementation in production

  1. Train on my computer. All training runs locally. Render only loads the trained models and uses them.
  2. Save the models. The trained models are saved as files (models/) and kept in the project.
  3. Flask app. The page receives a photo, cuts the leaf, takes the 26 numbers, and gives the answer, the magenta zone and the advice.
  4. Publish on Render. The app runs as a web service (gunicorn) with a PostgreSQL database for users, farms, plots, inspections and logs. Each push to GitHub updates it.

What the user sees

  1. Upload. The user takes a photo of one leaf with a phone and sends it, and says the variety if they know it.
  2. Analyze. The app checks the color and the spots and marks the zone it analyzed (yellow line).
  3. Receive. The user gets: healthy or sick, how sure the model is, the zone with signs of damage in magenta, and what to do for resistant or susceptible varieties.

Documentation and training for users

  • The page explains how to take a good photo: one leaf, up close, plain background, good light.
  • The page shows a warning when the confidence is low or when the cut does not look like a single leaf.
  • The page says what the app can and cannot do: it only knows rust and red spider mite, it is an estimate, and it is not a diagnosis.
  • These pages explain the method and the limits for anyone who wants to check the work.

Saved model and files

  • models/modelo_app.joblib: the selected Random Forest and the list of its 26 columns.
  • models/qlearning.joblib: the Q-Learning tables (resistant and susceptible).
  • models/referencia_monitoreo.json: the mean and spread of every feature in the training photos. The monitoring uses it as the reference (Phase 6).
  • Preprocessing. The Random Forest needs no scaler. The preprocessing is the code in caracteristicas.py (leaf cut and 26 numbers), shared by training and by the app, so both do exactly the same.

Dependencies and how to run it

Python libraries are listed in requirements.txt. To reproduce the project from the repository:

  1. Install. pip install -r requirements.txt
  2. Download RoCoLe (CC BY 4.0, link in Phase 1) and put it in the data/ folder. The photos are not in the repository.
  3. Make the tables. python extraer_caracteristicas.py and then python probar_mascara_automatica.py
  4. Train the app model. python entrenar_modelo_app.py
  5. Make the evidence. python generar_evidencia.py (tables and figures in evidencia/)
  6. Run the app. python app.py and open http://127.0.0.1:5000. On Render it runs with gunicorn.

Protocols

  • Confidence levels. The answer comes with a confidence level: high (80% or more), medium (65–80%) or low.
  • Safe advice. The advice always asks the user to check more leaves and to talk to a technician before applying any product.
  • Incidents. Any user can report a wrong answer or an error from the page Feedback (or from the inspection itself). The message is saved with the user, the date and the inspection. A technician or the administrator answers it and marks it as resolved. If it needs a fix or new training data, I note it for the next model version.
  • Feedback. Under every result there is a “Was this result right?” question. The answer is saved and counted in the monitoring page.
  • Review by a technician. A technician can confirm what is really on the leaf. That label is used to measure how often the model is right.
