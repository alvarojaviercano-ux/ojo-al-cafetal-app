Status: the system now keeps every inspection, every login and every error in its database. The page Monitoring (technician and administrator) shows the indicators below. The numbers are only as good as the real use so far, which is small.

Continuous supervision

Each inspection saves the date, the user, the plot, the result, the confidence, the model version, the response time and the 26 numbers taken from the photo. The event log keeps logins, failed logins, forbidden attempts, errors and slow requests (more than 5 seconds).

The drift in the app is a simple mean shift. The Population Stability Index (PSI) is calculated offline with generar_evidencia.py.

Maintenance and model versions

  • Every result stores the model version (package version plus the first 8 characters of the hash of modelo_app.joblib). So an old result can always be traced to the model that made it.
  • To update the model: train again on my computer with the new reviewed photos, check the results by plant, replace the files in models/, push to GitHub and check the Monitoring page. The old results keep their old version label.
  • Add photos of Colombian arabica (Castillo, Caturra) and of other diseases (Cercospora, Phoma) so they stop showing up as false positives.
  • Replace my assumed Q-Learning costs and rewards with real ones when I have them, and check the advice with a coffee technician.
